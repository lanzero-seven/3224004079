**1. 介绍自己**

我是一名广东工业大学计算机学院 24 级的学生，由于学校开展软件工程必修课，赴老师要求开展博客园的使用，我认为这是一个很好的记录和分享自己学习成果和心得体会的机缘。

在这里我可以向大家分享我的闪光点，我的特长是画画，我曾有过6年的系统绘画经历，我乐于将脑海中一切强烈浮现的标志性事物或场景通过画笔画下来；高中时我的数学几何图可以说是班上画的最好的，而我最喜欢的科目也是数学。虽说现在的专业是计算机，说实话从前我也不曾表现出任何对编程、开发的热爱，但是计算机与数学，在学习方法和某些理解逻辑上，大体还是一致的吧。同时，演讲也是我的爱好之一，为文字配上声情并茂、抑扬顿挫的声调可以让其所描述的场景更生动地呈现出来，这也使我享受万分。由此看来，相较于千篇一律、固守成规的工作，我其实更偏向体验与创造。我认为这在任何时候任何场景任何活动中都是催使我长久走下去的源泉。

我仔细查看了老师的底线要求，总结一句话就是不能抄袭，可以借鉴，但要标清来路，尊重他人研究成果。

**2. 现状、经验和计划**

**（1）**关于为什么选择这个专业，从现实来讲，当时高考填报志愿时无非就是看这个专业好就业且薪资高，而若联系上价值追求，我至今还未想明了，但绝不是毫无意义的。事物意义都是人为赋予的，当觉得没有意义时才会去思考 ta 的意义。

若问：离成为一个合格的 IT 专业毕业生，在专业知识、技能、能力上还差距哪些？

根据查看冗长的技术调查表，我从中抽取 6 项所认为的作为一名合格的 IT 毕业生特别重要的技能如下：

1. 维度一的需求对齐与代码健康度；

2. 维度一的验证深度与测试覆盖；

3. 维度一的工程复现性；

4. 维度二的云原生部署；

5. 维度四的开源杠杆；

6. 维度四的手动掌控力。

① 我目前的水平是2，即我能够独立完成任务，代码有测试、有规范，能跑通正常流程。

② 我想在课程结束后达到何水平：我对自己的要求并不高，仅仅想在课程结束后达到的水平是 4，我不想现在多么天马行空的想象自己能够通过这个课程达到怎样高的一个段位，只希望自己能够踏踏实实的先走到最基本的水平。即可以一个人利用 ai 完成一个好项目从部署到完成所有流程的工作，熟悉这过程中的具体情况。

③ 我计划通过什么手段提高水平：我计划听老师的话，先大体了解一遍教材中的设计内容，然后利用所学知识部署一个个人小项目，考虑其基于何现实问题，进而展开研究进行创新，从而产生并丰富项目方案规划，再进行代码编程进行复现，最后进行代码测试和维护来完成第一个个人小项目；接着和同学一起部署结构项目、团体项目，通过每一次的项目打磨和跟踪流程来熟悉其间的工作情况。

**（2）**阅读博客所得心得

a）我为何要来上课并且认真参与

关于我为何要来上课，来上课是一个学生的基本素养，是对老师和课程的尊重，是对自己的负责，当然也是受教学制度所圈。而关于我为何要认真参与课程，要么是为了听清楚学期末教学检测要求，要么就是该课程老师讲得的确生动风趣让我沉浸式体验课堂。但是大多数时候我是没有认真参与的，因为网络课程已经能够很好的让我捡起这门课程的绝大部分知识点，现实生活中能够坚持把教学授课讲得让人提起兴趣且津津乐道的老师实在太少了，但是不得不承认我们软件工程的老师讲课所举的例子的确幽默生动、深入人心。

b）我在大学中体验到了哪种师生关系，希望是什么师生关系

我在大学中既体验到了”陌生人“式的师生关系，也体验到了”餐馆与食客“式的师生关系，体验到了”狱警与犯人“式的师生关系，也体验到了”教练与学员“式的师生关系。我当然希望这门课属于”教练与学员“式的师生关系，作为学生，哪一节课不想如此。如果老师布置的作业对我来说有点困难，我首先会权衡这个作业是否值得我花费大量时间与精力去完成它，一旦下定决心，必会付诸行动尽力将其完成好同时还感叹其提高了自己的某方面的水平或能力。

c）针对”参考别人的资料，在别人工作的基础上继续开发， 这些活动和抄袭、剽窃的区别是什么“一问题，我认为前者与后者还是有本质区别的，前者是站在巨人的肩膀上进行属于自己能力范畴内的再开发，同时我们谨记巨人的付出成果，后者则是完全不顾他人知识产权进行无脑的照搬照抄，这种行为可耻得令人发指。

**（3）**今天的我，为将来所作的准备是，首先将课内知识学扎实，为之后考研做准备；其次在学术研究方面，将所学的知识、复现论文等工作和流程进行整理，从中获取创新思维，看看还有没有可以优化的地方；再者需要利用所学知识部署小项目，了解整个项目从提出到落地的整个过程内容，后期将其开源到 github 为今后找工作做准备；同时还要捡起之前的算法、代码编程知识，理清代码逻辑，丰富自己的代码量。

**（4）**这门课叫做软件工程，在项目规划上面，我计划先将课本较重要章节如”详细设计“、”实现”展开学习，了解开发一个小软件或应用程序的具体流程并自己尝试应用程序的简单开发；在代码方面，希望自己写出的代码具有良好的稳健性，不会因为录入数据稍微多一点就崩，至今，我在c语言的代码量已经超过 1000 行，python代码量 300 行，同时我考虑这学期增加 c++ 或 Java 代码的使用，希望可以付诸行动吧。

我对这个课程的期待就是老师可以一以贯之的执行个人项目、结构项目、团体项目的作业规划，（压力压力我吧否则我肯定也就不重视这门课了 bushi），再者便是**老师可以给学生提供一些适合我们的小项目引导和主题推荐**，毕竟如果让我们自己来搜罗的话还不知道哪些项目价值高不高、好不好做、做起来有没有挑战性、学生感不感兴趣。俗话说得好，兴趣是灵感的源泉，而这门课最终成果的源泉也归于兴趣。我希望这节课可以有趣附带着挑战地度过，我不想当助教虽然说当助教确实可以多和老师接触并讨论想法，了解到许多同学不一样的创新点，但是当下我并不想当。

为了有资格入职一流的软件公司/互联网/人工智能公司，虽说当下人工智能盛行，ai 写出来的代码一键运行，代码量早已不能成为考核的唯一标准，但是对于正常的代码内容的理解和整体的部署仍然是作为一个合格程序员最基本的要求，如此看来，基本程序员的代码量上千行都是必然，更遑论科研工作者呢？我之前看过 ai 于医学影像脑肿瘤 MRI 模态缺失分割的一篇论文复现 demo，每一个小操作都有上千行代码，而我去复现这篇论文，调整数据量后我能否再更改代码使其运行起来，必然要了解整体数据流的流动，所采用的模型部分模块的更改。所以我认为越高代码量，考验的不仅仅是局部的代码理解和调整，更是对整体能够运作起来的统筹和布局。

我打算平均每周拿出多少小时用在这门课上？据我所知我现在写这篇随笔就用去了我 3 个小时的时间，而且还是阶段性加起来的，所以也许几个小时也行十几个小时具体我也说不清，看看工作量强度吧。我打算选 C: 比以前的课稍多一些。
